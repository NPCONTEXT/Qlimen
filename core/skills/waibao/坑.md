# waibao 派工的坑（从 SKILL.md 拆出，SKILL.md 里只留安全和真假相关的 4 条）

- `--dir` 不能是工作区顶层（`<工作区>` 本身，它下面有禁区 `工人家.nosync`），脚本会拒绝，要给具体子目录。
- 任务书要把边界口径写死（标题行算不算、简称算不算），否则工人会自己定一种；让它给「行号 + 原文摘录」，摘录可以用子串比对。
- 成本参考（2026-10-04 实测，高峰价）：通读 6.8 万字约 ¥0.38，20 万字约 ¥0.74，输出含思考，估算要留余量。
- 退出码 3 是失败、超时或越界（2026-10-09 起没有熔断），看回执里的错误和越界记录再决定；同一方法失败 2 次就停下汇报。
- `--out` 的结果文件夹必须在 `--dir` 里面，没有会新建；写文件的工人仍没有命令行和联网。写到文件夹外：系统沙箱挡掉，脚本当场停掉、回执标 ‼。
- Kimi 登录失效（报 `authorization grant is invalid`）：用户运行 `kimi login` 前要先运行 `$QLIMEN_HOME/core/bin/qlimen-unlock`，因为登录会改写加锁的 `~/.kimi-code/config.toml`（10-09 没解锁时报 EPERM，但凭据已更新、能用）。登录后把 `~/.kimi-code/credentials/kimi-code.json` 复制到 `<工作区>/工人家.nosync/kimi/credentials/`；凭据副本别放进任务目录（会外发、会进 iCloud）。
- 估算花费按高峰价，偏高；超时被杀时最后一步不计入。金额不是账单。
- 每次调用会在 dsh / kimi 的会话列表里留一条记录。
- 联网的工人，回执和结果文件里会列出它用过的全部搜索词和网址；带 ‼ 的是过长条目，必须看一眼有没有把本地内容带出去。
- 要「对照本地数据核对公开信息」就拆两步：先让本地工人或主模型摘出要核对的条目，再把条目写进联网工人的任务书（联网工人读不了本地）。
- 派工人看图（主模型没有视觉时）：任务书写图片路径、具体问题，并写明「只用读图工具看，不要跑 OCR 或脚本分析」（实测不写会自己跑 30 次命令，¥0.69、5 分半）；结论写明是哪个工人看的。
- 整理文件：让 k28 出「操作清单」（只有 mkdir / move / rename），把清单存成 JSON 文件，逐条审过，先 `waibao apply --dir <根目录> --list <清单.json> --dry-run`，再去掉 `--dry-run` 执行；回执里有撤销命令（`waibao undo`）。脚本不支持删除和覆盖，要做就自己接手并先问用户。
- 进度和未核实项看各任务目录的 `TODO.md`；改了脚本或规则要同步更新 waibao 自身文档。
