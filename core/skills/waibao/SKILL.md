# 工人名册与派工（waibao）

## 什么时候用我
要读的量大（约 2 万 tokens、一两千行以上）、能拆成只读问题、且目录在 `<工作区>/` 内（`预算.json` 的 `allow_roots`）时用。
读量小、要改文件、要做决定、依赖对话上下文、涉及 Blender / 浏览器的活，自己干，不派。
需要联网的只读调研可派：命令里加 `--web`（只对 k28 / k3，`--dir` 可以不给），计划里写明「联网」。联网工人读不了本地文件，要用的本地内容写进任务书；不加 `--web` 的工人没有联网工具。
要工人跑很久、边做边存结果（如 K3 长任务）：k3 / k28 加 `--out <--dir 里的结果文件夹>` 和 `--timeout 秒`；业务产物只写进这个文件夹，系统沙箱另外放行工人数据目录、临时目录和 `/dev`（别处沙箱挡、脚本也盯着），回执列出写了哪些文件。2026-10-09 实测 K3 写 2 个文件 23 秒成功。

## 名册（只记事实；派不派、派谁由主模型自己定）
| 工人 | 会什么 | 计费与速度 | 实绩与限制（截至 2026-10-06，来源：`core/data/用量日志.csv` 和各 harness 任务复盘） |
|---|---|---|---|
| `k3` | 用户指定的第二审查（AGENTS 第 2 节）；难分析；能看图；加 `--out` 可跑长任务写结果 | Kimi 会员额度，日上限 100 次（只提醒）；审查 41–484 秒，给的文件越多越慢 | 钩子修复 10 条意见 8 条成立，收尾四项 16 条采纳 12 条；读不到加锁目录，约 15% 意见因此落空 |
| `flash` | 通读长文（约 2 万 tokens 以上）、看图 | DeepSeek 余额按量扣，日上限 ¥30（只提醒）；冒烟 3–6 秒 | 长篇小说通读试跑 88 条 0 编造、84 条行号全对；只读本地，命令行和联网都关了 |
| `k28` | 杂活（翻译、摘要、整理清单、出文件整理清单）、联网搜索（加 `--web`） | Kimi 会员额度，日上限 200 次（只提醒）；8–80 秒 | 账本里 7 次全是冒烟和自查，真实任务还没用过 |
- Kimi 走会员额度（按次），DeepSeek 扣余额（按量）。
- 没有别的模型。v4-pro 和中转站用户明确不要。
- 工人默认只读；加 `--out` 的业务产物只写那一个文件夹（沙箱例外见上）。方案、交接、验收清单由主模型亲自写（AGENTS 第 2 节）。

## 请 K3 做第二审查
- 后台派出，不等它；回来后逐条核实，再转告用户，由用户定（AGENTS 第 2 节）。
- 外部视角（2026-10-10 定）：K3 经 waibao 的工人模式本来就不读全局协议，只带一页工人守则（只读、证据格式）；任务书只给要审的材料和要回答的问题，让它判断对不对。换干净配置的 Codex 当外部审稿人，流程见同目录 `外部审稿.md`。
- 提速：只给方案和关键文件，要它「最多列 N 条最重要的问题」；它读不到加锁的文件（AGENTS、派工脚本、入口配置等），要用到的事实直接写进任务书。

## 怎么派
1. 先在回复里写一句话：派谁、做什么、预估成本、结果拿来干什么。同一句话填进 `--plan`。
2. 调用。预计超过 1 分钟或要并行时用后台 Bash，完成会自动通知。`$QLIMEN_HOME` 指 Qlimen 仓库的绝对路径，`install.sh` 运行时会打印出来；建议在 shell 配置里 export，或直接换成绝对路径。
   ```bash
   $QLIMEN_HOME/core/workers/waibao k28 --dir <具体子目录> --tag <短标签> \
     --plan "<那句话>" --task "<任务书>"
   ```
   任务长就用 `--task-file`。`waibao --status` 看当天用量。在 Claude Code 里，要匹配 settings 的免弹框规则（`permissions.allow` 里的 `Bash(<QLIMEN_HOME>/core/workers/waibao *)`），就得把 `$QLIMEN_HOME` 展开写成绝对路径、单条命令调用（不加 `cd`、管道、`~`），否则会弹权限框。
3. 任务书只写：要回答的问题、看哪些文件或怎么找、要什么粒度。给路径不给内容；守则和四段回执格式脚本会自动加。
4. 回执在 40 行内，每条结论带 `文件:行号`，全文在回执给出的路径里。**抽查 2–3 条再采信**；出错代价高的结论自己读原文。
5. 汇报时写明派了什么、给谁、花了多少。

## 预算（只记账、只提醒，不拦；数字在 `core/workers/预算.json`）
日上限 DeepSeek ¥30/天、k3 100 次/天、k28 200 次/天；超长上限 600 秒（不给 `--timeout` 时到点收工，给得更长照跑）。超了脚本在派工前和回执里提醒，不拦（2026-10-09 用户定：用户批准高于预算）。上限内自主派；要超上限先问用户，批了照派，`--plan` 里写明用户原话。改预算数字、换账本、绕过脚本直接调 `dsh` / `kimi`，先问用户。
被拒绝（退出码 2）现在只剩目录、档案、参数这类安全原因，停下告诉用户。

## 坑
- 工人会编。没行号的结论当没说；工人给的数字和链接一律当未核实，要进正式数据的按项目自己的核实规则处理（核实不了就标「存疑」）。
- 不要设 `WAIBAO_*` 环境变量，那是自查用的；不要放宽三份工人档案（`工人-kimi.md`、`工人-kimi-联网.md`、`工人-kimi-写.md`）的工具白名单，也不要把 `adapters/dsh/dsh-flash.patch.yml` 里关掉的工具打开：两个壳的无头模式从不询问，这几处是唯一的闸。
- 钩子 guard（2026-10-09 起）：同一条命令里有壳名、后面又跟 `-p` / `--prompt` 或 `headless`，就弹框问用户（Claude Code、DSH 实测会弹；Codex 会不会弹没核实），不再直接拦；单引号里的文字、结束符带引号的 heredoc（`<<'EOF'`）正文、注释不算；双引号和 `<<EOF` 正文里的 `$( )`、反引号会真的执行，照样检查，写文档一般不会触发。弹了框由用户定，不改写法、不拆词绕开。
- 工人的读文件工具不按路径拦（2026-10-06 实测 k28、flash 各读到工作目录以外的 3 个文件）。现在的防线：读本地的工人没有联网和命令行，联网的工人读不了本地；回执的「越界记录」列出它读过的目录外路径，‼ 是禁区、派工范围以外（含 `/tmp`）或用了不该有的工具，这时回答不打印、当成不可信。要工人看的东西先放进任务目录。这是尽力而为：读到的内容仍会发给模型服务商、仍会写进回答。
- 其余坑（`--dir` 限制、任务书口径、成本参考、退出码、联网审计、拆两步核对、看图任务书、整理文件、会话记录）见同目录 `坑.md`，第一次派某类活前读一遍。
