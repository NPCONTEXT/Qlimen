# 用干净配置的 Codex 做外部审稿（从 SKILL.md 拆出）

2026-10-10 开源审核时实际这么做的。目的：审稿人像第一次看到这个仓库的外人，不带核心协议、私有协议、skill，只拿材料和问题判断对不对；只读这条边界由命令行参数保证，不靠协议（AGENTS 第 2 节）。
这一步不经 waibao、直接调模型，花的是用户的 Codex 额度：按 AGENTS 第 3 节先说明做什么、花多少、向谁付费，等用户批准。

## 步骤
1. 在系统临时目录建一个空的 `CODEX_HOME`，只复制登录凭据 `auth.json`；不复制 `AGENTS.md`、`config.toml`、`hooks.json`、`skills/`、私有协议。临时目录不放进工作区（会进同步盘、会被工人读到）。
   ```bash
   T=$(mktemp -d); mkdir "$T/home"
   cp ~/.codex/auth.json "$T/home/"
   ```
2. 先确认上下文干净：在要审的目录里运行不调模型的 `codex debug prompt-input`，看输出里没有核心协议（如「诚实 > 安全与授权」）、私有协议和 skill 列表。参数以 `codex debug prompt-input --help` 为准。
   ```bash
   CODEX_HOME="$T/home" codex debug prompt-input
   ```
3. 审稿，只读沙箱、不留会话：
   ```bash
   CODEX_HOME="$T/home" codex exec -s read-only -C <要审的目录> --skip-git-repo-check --ephemeral \
     -o <意见文件> "<问题>"
   ```
4. 审完删掉整个临时目录 `$T`（含凭据副本），再 `ls` 确认它已不存在。

## 问题怎么写
- 只说「你是第一次看到这个仓库的外部审稿人」，不给背景、不转述协议、不说作者想听什么。
- 过头和保守两个方向都要：文档说的比代码做到的多、证据撑不住的结论；也要明明做到了却没写、说低了的地方。
- 要它每条给 `文件:行号`、原文摘录、问题、建议改法，按严重程度排序；声明只读、不改文件。

## 坑
- Codex 会按自己的习惯往上级目录找 `AGENTS.md`，可能列出文件名（不读内容）。要审的目录别放在有私人文件的上级目录下，拿不准就先复制到临时目录里审。
- 只读沙箱只挡写，不挡读：它能读到盘上别的文件。
- 意见回来同样逐条核实再转告用户（2026-10-10 那次 15 条，其中 guard 漏判双引号里的命令替换、撤销不校验路径等代码问题此前没发现，已修）。
