# 工人分工（派什么活给谁）

qlimen-flow 的附属文件。派工只认这一份，`waibao` skill 也指到这里；要改分工只改这里，别在别处另写。

工人分工（2026-10-05 用户定，同日晚调整为 Kimi 多干活）：决策只有总工和用户。Kimi 会员额度多，DeepSeek 是余额，能派 Kimi 就派 Kimi。
| 活 | 派谁 |
|---|---|
| 查资料、联网搜索、读网页 | k28 加 `--web`；要深挖、交叉核对升 k3 加 `--web`。联网工人读不了本地文件，要用到的本地内容写进任务书 |
| 翻译、摘要、整理清单、改写等杂活 | k28 |
| 整理文件 | k28 出操作清单 → 总工审 → `waibao apply`；删除/覆盖/破坏性操作总工接手并先问用户。只能在派工范围内（`预算.json` 的 `allow_roots`），范围外的目录（如桌面）到时由用户单独授权 |
| 审查方案、挑漏洞、难分析 | k3（唯一审查员，总工核实后取舍） |
| 读图、本地输入超过约 2 万 tokens（含长文摘要、翻译） | flash（只交材料和建议，不参与审查结论） |
| 写代码、写正式文档 | 总工自己写，工人只交材料 |
| 写方案、交接、验收清单 | 总工亲自写，不派工人；所有方案都算。只管「写」：调研派工、K3 审查方案、flash 扫现状照旧（2026-10-05 用户：「交接方案是很关键的，不能派工人」；10-06 确认是全部方案、只管写） |
一句话：读图或本地输入很长 → flash；其他先派 k28，不够再升 k3。Kimi 当天次数到 90%（回执会提示）或额度用光 → 改派 flash。
工人分两种（2026-10-06 工人加固）：不加 `--web` 是本地只读，能读文件、没有联网工具；加 `--web` 是联网，只能搜索和读网页、读不了本地文件，`--dir` 可以不给。flash 只有本地只读，命令行和联网都关了。要「对照本地数据核对公开信息」就拆两步：先让本地工人或总工摘出要核对的条目，再把条目写进联网工人的任务书。
联网工人的回执会列出全部搜索词和 URL，带 ‼ 的过长条目总工必须看一眼是否带出本地内容。
回执里的「越界记录」：‼ 是工人读了禁区、派工范围以外的地方（`/tmp` 也算）或用了不该有的工具，这次的回答不打印、当成不可信，先查清再说；不带 ‼ 的普通越界，看一眼是不是任务书引它过去的。要工人看的东西先放进任务目录。
所有工人只读、经 `waibao` 派出，不得写任何文件，尤其不得碰协议、配置、中转站设置、`core/`；要改由总工出 diff，用户批准后落盘。读图（2026-10-05 用户定）：总工读不了图（中转 Opus）时，定级就标出「要看图」的环节，直接派工人看图，不先问：优先 `waibao flash`（DeepSeek-V4.1-Flash，图压到约 300 tokens，最省），flash 失败或看不清再 `waibao k3` 兜底；任务写图片路径、具体问题和「只用读图工具看，不要跑 OCR 或脚本分析」（实测不写会自己跑 30 次 bash，¥0.69、5 分半；2026-10-06 起 flash 的命令行已关，这句仍要写，免得它白费步数），结论写明是哪个工人看的。
