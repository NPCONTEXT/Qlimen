# 验收清单写法（verify 能自动检查的格式）

写在方案第 5 节，每条一行，以 `- [ ] ` 开头。路径可用绝对路径、`~/` 开头，或相对方案所在目录。

| 写法 | 检查什么 |
|---|---|
| `- [ ] file: 产出/报告.xlsx` | 文件存在且非空 |
| `- [ ] dir: 产出/图片 >= 10` | 目录存在，且至少有 10 个文件 |
| `- [ ] xlsx: 产出/报告.xlsx rows >= 14` | 第一个工作表的数据行数（不含表头）≥ 14 |
| `- [ ] xlsx-nonempty: 产出/报告.xlsx 列=链接,数值` | 指定列每一行都不为空 |
| `- [ ] csv: 产出/数据.csv rows >= 100` | CSV 数据行数 |
| `- [ ] contains: README.md "启动方法"` | 文件里包含这段文字 |
| `- [ ] url: https://example.com` | 链接能打开（HTTP 2xx/3xx） |
| `- [ ] urls-in: 产出/报告.xlsx` | 文件里所有链接都能打开（逐个请求，可能慢） |
| `- [ ] cmd: python3 test.py` | 命令退出码为 0（在方案目录下执行，最长 60 秒） |
| `- [ ] media: 产出/成片.mp4 duration 70-90` | 音视频时长（秒）在范围内；需要 ffprobe |
| `- [ ] manual: 用户确认配色` | 机器查不了，交付时请用户确认；verify 只列出不判定 |

规则：
- 能用前 10 种的，不要写 `manual:`。
- `manual:` 以外的条目如果写成没有前缀的大白话（例如「效果好」），`verify --plan` 判为不合格。
- `cmd:` 只放只读、无副作用的检查命令（跑测试、校验格式）；不要放安装、部署、删除。
- `url:` / `urls-in:` 会真的发请求，只用于公开链接；需要登录态的页面写 `manual:`。
- 文档类产出（skill、说明书、交接）要有核对内容的条目：挑几条关键事实写成 `contains:`，事实照源文件抄，不照自己的笔记写。只查「文件在、含某个词」等于没查（2026-10-06：一份 skill 写错 7 处，验收全绿）。

按任务类型的常用验收项见各作业手册（`qlimen-manual-*`）。
