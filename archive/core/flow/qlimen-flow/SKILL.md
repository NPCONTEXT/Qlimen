# qlimen-flow：从需求到交付

## 什么时候用我
需求不是一步能完成就用。L0 小改动（改一行、改个字、回答问题）不走本流程，直接做。
目标：把返工压在动手之前。规则见 AGENTS 第 2–4 节，本文件只写怎么做。

## 1. 定级（先写一行「定级：Lx，理由」）
- L1 普通产出：单一产出物、不碰系统配置 → 调研 + 方案 → 用户批 → 执行
- L2 跨多个文件/改配置/要联网/要登录态 → L1 + K3 审查方案
- L3 网络/代理/系统设置/部署/可能切断自己连接/花钱/删数据 → L2 + flash 扫现状交材料 + 写回滚预案
拿不准往高一级定。

工人分工（派什么活给谁、读图、联网工人的回执怎么看）：见同目录 `工人分工.md`，派工只认那一份。决策只有总工和用户；所有工人只读、经 `waibao` 派出。

## 2. 调研（低成本优先，按顺序）
1. 任务目录里的 `TODO.md`、`交接.md`、`方案.md`；`history-archive` 里有没有做过类似的
2. 对应作业手册（`qlimen-manual-*` skill）的「调研清单」
3. 本机现状：相关文件、配置、`--help`、版本号
4. 官方文档 / 免费检索
5. 要联网查的派 k28；本地读量大（约 2 万 tokens 以上）派 flash，见 `工人分工.md`
调研结论写进方案第 1 节，分「已核实」「未核实」。

## 3. 方案
复制 `方案模板.md`（与本文件同目录）到 `任务目录/方案.md` 填写；验收项必须机器能查（写法见 `验收模板.md`），从作业手册挑，再加本任务特有的。
L2/L3：把方案草稿派给工人找茬，合并意见；冲突处自己读原文核实，写进「会诊记录」。

## 4. 锁定
先跑 `$QLIMEN_HOME/core/bin/verify --plan 任务目录/方案.md`，过了再给用户看。
用户明确批准后，在方案头部把状态改成 `已锁定`，并写批准时间。

## 5. 执行
连续执行，按方案第 4 节逐项勾选 `TODO.md`；每项（超 30 分钟的按小段）动手前一句话阶段预告，做完一句话结果（AGENTS 第 2 节）。
要偏离方案（改范围、换做法、加步骤）→ 停，写「变更申请：原因、影响」，等批准后把方案版本 +1。
## 6. 验收与交付
跑 `verify 任务目录/方案.md`；有失败项就继续修，不许报完成。
交付：结论、产出物路径、验收结果、未验证项、本次花费（看 `waibao --status`）。
最后在任务目录写 `复盘.md`（≤10 行：哪里返工了、手册该补什么），并把可复用的坑补进对应作业手册。
## 7. 交接
任务目录始终有 `方案.md`、`TODO.md`、`交接.md`，按同目录 `交接模板.md` 写（何时写、写多细见模板开头）；用户每句要求、纠正、吐槽当场记进交接；派工人前背景先写进交接，让工人读文件。
## 坑
- 跳过调研直接动手，是返工的头号原因；「我记得」不算调研。
- 验收项写成「效果好」「没问题」这类形容词，等于没写；`verify` 会把它判为不可检查。
- 工人报告是线索不是结论：没有 `文件:行号` 的当没说；抽查 2–3 条再采信。
- 受保护文件写入报 `Operation not permitted` 是加锁，不是故障：出 diff 请用户解锁，不绕过（AGENTS 第 7 节）。
