# 数据采集与报告

## 什么时候用我
产出是表格、报告或数据文件。已有专用采集 skill 的先加载它，本手册只补通用部分。
来源：网页数据采集任务的教训汇总、一个数据展示网站的维护说明书、整理季度信息（2026-09）。

## 调研清单
1. 有没有现成脚本/skill/上次的 run 目录：有就增量补跑，**不从头重跑**
2. 数据源要不要登录态；用户浏览器是否已登录（先跑登录预检，掉了就请用户登录，别硬跑）
3. 平台近期是否改版：旧配置「以前能跑」≠ 现在对；报未命中先 dump 页面结构
4. 产出格式：列名、文件名、排序、0 值和缺失怎么填——问清或照上次的表
5. 量大的只读活（通读 PDF、扫几百行数据找矛盾）派 flash；联网查资料、核对公开数据派 k28

## 方案必写
- 「没有 / 0 / 抓不到」各自的判据（例：无登录态打得开=填 0，打不开=删行）
- 核实不了的数怎么标（例：那个网站项目的规则是标「存疑」，不逐条追查到底）
- 先试 1–2 条，确认字段对了再批量

## 验收清单（挑用）
- [ ] xlsx: <表> rows >= <N>
- [ ] xlsx-nonempty: <表> 列=<关键列>
- [ ] urls-in: <表>　　（公开链接才用；需登录的写 manual）
- [ ] cmd: python3 <体检脚本>　　（项目有体检脚本必跑）
- [ ] manual: 用户抽查 3 条

## 坑（都踩过）
- **链接/数字不得凭截断输出补全**：长链接打印会被截断，补后半段必错；从原数据精确读取，写完逐条 curl
- 数字和链接必须来自真打开过的页面；工人给的一律当未核实，另派一轮反向核实
- 「抓不到」先怀疑自己：点了没反应可能是开了新窗口；页面属性（`onclick`、`data-row-key`）里常有现成 URL；下结论前问用户
- 用正则取链接只匹配 ASCII，否则会连中文括号一起吞进去
- JSON 数据用脚本整体读写（`json.load`→改→`json.dump(ensure_ascii=False, indent=2)`），禁止手抠文本
- 跨榜/跨表 id 要全局查重
- 标题匹配先归一化（只留中文/数字/字母）；失败往往是「翻到了没认出来」
- 收尾清理按「用过的全部 session/标签页」逐个清，不是清一个就说干净
- 后台跑长采集要显式给足 timeout（10–30 分钟）
