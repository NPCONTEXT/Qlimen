# 维护 Qlimen

## 什么时候用我
要动 `$QLIMEN_HOME/` 里的东西，或它在各工具里的挂载（`~/.claude/settings.json`、`~/.claude/CLAUDE.md`、DSH 的钩子补丁、skill 软链接）时用。改脚本、改挂载（给挂载文件加锁解锁也算）按 L3 走，只改文档按 L2。
来源：2026-10-06 的接入、巡检、钩子修复、工人加固几个任务（`<工作区>/harness接入实测/`、`harness钩子修复/`、`harness收尾四项/`、`harness工人加固/`、`harness小修补坑/`）。

## 调研清单
1. 读 `adapters/<工具>/挂载说明.md` 和 `core/workers/自查记录.md`：现在挂了什么、测过什么、已知限制
2. 要改的文件在不在 `core/bin/保护清单.txt` 里；在就走「出 diff → 用户解锁 → 落盘 → 用户加锁」
3. 事实对着源文件核：脚本读源码，配置读文件，不照别人的交接或自己的笔记写
4. 改脚本前把线上版本拷进任务目录当「现状」，新旧对比和回滚都靠它
5. 现成的样例和测试脚本：`<工作区>/harness钩子修复/测试/`（`样例.json`、`跑测试.py`）；改 `waibao` 用 `<工作区>/harness工人加固/测试/`（`假工人.py`、`跑测试.py`，零花费，`--installed` 测线上）。这些是作者工作区里的任务目录，没收进仓库；仓库现行的测试在 `tests/`

## 方案必写
- 改拦截类逻辑（guard）：先把「现在拦得住的」列成底线；哪些「旧拦新放」是允许的、为什么，逐条写
- 会让检查悄悄失效的规则不靠推断（按名字猜、按当前目录猜），用显式标记或固定配置
- 两边共用的脚本：写明对另一个工具的行为变化；测不到的那一边列进「未验证」
- 回滚分两种起点：还没加锁时、加锁之后
- 方案里新选的目录、新写的验收项，先拿真东西对一遍：目录对着 `预算.json` 的 `deny_roots`（或用 `waibao --dry-run` 试），验收项对着自己要写的文件格式

## 验收清单（挑用）
- [ ] cmd: /usr/bin/python3 <任务目录>/测试/跑测试.py --installed
- [ ] cmd: cmp <草稿文件> <线上文件>　　（每个改过的文件一条）
- [ ] contains: <测试结果>.md "新版漏拦 0"
- [ ] contains: <改过的文档> "<对着源文件核过的关键事实>"
- [ ] manual: 用户在新会话里确认规则和钩子仍在生效

## 坑（都踩过）
- 钩子脚本、settings.json、skill 软链接改完当场生效，不用重启；所以装之前先离线喂样例
- 钩子坏了是静默放行，不报错：装完对线上版本再跑一遍测试，并做反向检查（把旧版当新版喂，测试要能报出失败）
- 测 guard 不真调壳：用只打印文字的命令，拦住算通过，没拦住也不花钱
- 测 Stop 钩子只能真的结束回合：结束前那句话要写成拦住、没拦住两种情况都说得通
- 换线上脚本用「同目录临时文件 → 设权限 → `mv -f`」，另一个工具可能正在跑
- 测试用环境变量 `QLIMEN_TMP` 把状态目录指到临时目录，别碰 `/tmp` 里真的那两份
- 判「例外放行」（如查帮助）最容易被引号、续行绕开：先把引号里的内容盖住再判
- 派 K3 审查：要它看的文件先拷进任务目录；它按守则不读工作目录以外，读不到的事实直接写进任务书
- 工人的读文件工具不按路径拦（2026-10-06 实测 k28、flash 都读到工作目录以外；敏感文件名会不会另有拦截没测）。工人加固后断的是往外发的路（flash 关工具、kimi 分本地和联网两种档案），读靠回执的「越界记录」标出来：任务书别引它去读别处，要它看的东西放进任务目录
- 改文档前，先在各任务的 `方案.md` 里搜有没有 `contains:` 验收项引用要改的那句话：结束检查的钩子会重查，字面对不上就拦。`cmd:` 类的验收项是交付当时的快照，后来的任务改了同一个文件就不再成立，不用回头改旧方案
- `verify` 的 `file:` 要求文件非空；写进文档的时刻先 `date` 或用 `stat` 核，不推算
