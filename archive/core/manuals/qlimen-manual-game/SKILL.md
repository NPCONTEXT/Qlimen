# 游戏脚本与自动化

## 什么时候用我
产出是会自己点、自己跑的脚本。已有专用 skill 的（如某款手游的日常脚本 skill）先加载它。
来源：几款手游的日常脚本和挂机脚本、网页数据采集的浏览器驱动（2026-09～10）。

## 调研清单
1. 已有脚本、挂机聚合器里的注册（如 `tools.json`）、设备号、分辨率基准、OCR 工具
2. 用户定的流程顺序和取舍（例：哪些次数拉满、哪些跳过、体力谁规划）——逐条问清写进方案
3. 游戏/页面最近有没有更新、活动有没有上下线：界面元素会漂移
4. 有没有截图/探针工具（`probe.py shot|tap|back`），没有先做一个
5. 跑起来会不会占用户的鼠标/前台窗口

## 方案必写
- 每个步骤怎么判「到了这个界面」「已完成」，找不到时怎么办（滑动重找 / 回主菜单 / 跳过并报告）
- 用户没实测过的分支标「未实测」
- 失败的现场怎么留（截图存哪）

## 验收清单（挑用）
- [ ] cmd: <python> <脚本> --help
- [ ] cmd: <python> -m py_compile <脚本>
- [ ] dir: shots/<本次> >= 1　　（实跑留了截图）
- [ ] manual: 用户看一次完整实跑，或看实跑日志与截图

## 坑（都踩过）
- **按钮位置不写死**：页签、列表随活动和完成状态漂移/重排，先 OCR 找文字再点同一格的按钮
- 相似按钮会认错（相邻卡片上的同名按钮）：按卡片范围配对标题，跳过带「已完成」的
- 「点击空白处关闭」那行字本身可能是入口；点角落空白
- 「返回」可能跳到别的页；统一回主菜单再进
- 弹窗还在不代表还有次数，读剩余次数再决定
- 不写死 sleep，轮询等待界面就绪；`exec-out screencap` 取原始数据比 PNG 快
- 浏览器自动化：合成 `click()` 对 SPA 无效，用真实点击并先把标签页切到前台；后台窗口截图可能是白板，用 CDP 截图
- 弹窗 alert 会卡死整个标签页，必须自动关闭并报出内容
- 用户口述过的流程当场写进 skill/代码，「我记得写过」≠ 写过
