# 协议来历

> 核心协议 `core/rules/AGENTS.md` 每一条从哪来，作者和模型到底需不需要它。来历查不到的写「未知」，不补编；证据一列按下面图例里的五种判定写。为什么整体只留这份协议，见 [设计取舍.md](设计取舍.md)。

## 怎么读

**结论**：这份协议的大部分条款早于重型 Harness，是作者在 DeepSeek、Kimi 身上踩坑写下的；10-06 瘦身时默认保留原文，只改了和停用部件挂钩的句子，并补回旧版里丢掉、仍然有用的半句。证据这边，10-10 逐条取证的 32 条，每条都在记录里找到了对应的行为：24 条能对上条款，8 条分不清是条款起的作用，还是模型自带的习惯或别的机制。

- **来历**的来源有四种：
  1. 作者找到的 9/15 DeepSeek 时期协议版本（下称「9/15 版」）。
  2. Kimi 的记忆导出（2026-09 生成，属于二手记录）。
  3. 10-05 起的协议备份。最早一份已经带 Harness 字样，更早的原版没找到。
  4. 10-06 的瘦身方案（v1–v5）及之后的修订。
- **需不需要**的证据有四种：
  1. 10-06 瘦身时，Opus 查了自己在作者环境里的 18 个历史会话和 5 份复盘。
  2. 10-06 评估，依据 38 条派工账本。
  3. 10-10 第一轮行为统计（见 [实测记录.md](实测记录.md) 第 2 节）：按回合用正则数，粗口径；前后对比是观察，不是对照实验；DSH flash 精简期只有 9 个回合，Codex 主会话精简期只有 19 个回合。
  4. 10-10 第二轮逐条取证：把三个环境的会话记录拉成一份语料（共 44,797 条，含用户消息、助手文字、工具调用、工具结果），每条条款先用几种同义说法的正则搜，再人工读命中处的上下文、剔掉误报。既报条数也报会话数：Claude 一个会话常连续几百轮，三件套建一次后一直更新，只按回合算会被稀释。计数是粗口径，带「约」的是人工剔过的；会话数的口径和实测记录不完全一样。
- 作者 10-06 定的原则：精简要「尽量保持原意」。所以举证责任是反的：删一条要先说明它为什么没用，留一条不用。

**证据一列的五种判定**（每格开头加粗的那几个字）：

| 判定 | 什么意思 | 不能读成 |
|---|---|---|
| 找到行为且能对应条款 | 记录里有模型按这条做的实例，并且能对上这条：模型自己引用了条款；或者同一个模型接协议前没有、接后有；或者条款原话被照着用 | 效果一定大。多数是观察，不是对照实验 |
| 找到行为但无法归因 | 行为找到了，但没有协议的模型也这样做，或者派工脚本、加锁这类机制本来就限住了，分不出这句文字起了多少作用 | 这条没用。只是这批记录证明不了它的增量 |
| 未纳入统计 | 第二轮取证没覆盖这条。格里的实例或数字来自更早的复盘和评估，没有按这五种判定重核 | 没有证据 |
| 搜了没找到 | 按几种同义说法搜过，没命中 | 没发生。措辞千变万化，正则覆盖不全，也可能做了但没说出来 |
| 确实没有证据 | 搜过，并且人工通读过相关会话，或者这种场合在记录期内根本没出现过 | — |

**「没搜到」不等于「没发生」。** 这份文档早先把没专门统计的条款一律写成「没有专门证据」，把「关键词没搜到」当成「没有证据」，也把「协议里没直接写这个行为」当成「没帮助」，作者指出太保守。这一版两头都防：没有协议的模型也会做的，归「无法归因」，不算到 Harness 头上；条款原话被抄进派工提示、后台标题照着例句写这类间接作用，照实写进来。
