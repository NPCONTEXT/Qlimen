# 统计脚本

## 这是什么

`统计.py` 读你本机三个工具的会话记录（Claude Code、DSH、Codex），按同一套口径数出和 Qlimen 协议条款对应的行为：状态标记、阶段预告、三件套、区分已核实/未验证、先查后动、回合末交代状态、耗时说明。它按你给的阶段（比如「接入 Qlimen 之前 / 之后」）分开汇总，输出一份 Markdown 表。

[docs/实测记录.md](../../docs/实测记录.md) 第 2 节的数，就是作者用这套口径在自己的记录上算的。你可以拿自己的记录复现同一套统计。

脚本只读：不改会话文件、不联网、不调模型、不花钱。

| 文件 | 用途 |
|---|---|
| `统计.py` | 主脚本 |
| `阶段.example.json` | 阶段配置示例，日期是占位 |
| `dsh_read.mjs` | 解压 DSH 会话：DSH 的会话文件是多个 zstd 帧首尾相接 |
| `自测.py` | 用假数据测脚本，不读你的真实记录 |

## 要什么

- Python 3.9 以上，系统自带的就行，只用标准库。
- 读 DSH 会话要 Node.js 22.15 以上，用它内置的 zstd 解压。没有就自动跳过 DSH，汇总表的「数据来源」里会写原因。

## 怎么跑

1. 把 `阶段.example.json` 复制到仓库外面，比如 `~/qlimen-统计/阶段.json`，把日期改成你自己换协议的时间。真实日期别提交回仓库。
2. 跑统计，汇总表写到标准输出：

   ```bash
   python3 tools/统计/统计.py --stages ~/qlimen-统计/阶段.json > ~/qlimen-统计/汇总.md
   ```

3. 想先确认脚本在你的机器上工作正常：`python3 tools/统计/自测.py`。它在临时目录里造假数据，跑完删掉。

| 参数 | 作用 |
|---|---|
| `--stages 文件` | 阶段配置。不给就把所有记录算成一个阶段「全部」 |
| `--claude 目录` | Claude Code 会话目录。默认 `~/.claude/projects`，也可以只给其中一个项目目录 |
| `--dsh 目录` | DSH 会话目录，默认 `~/.dsh/sessions` |
| `--codex 目录` | Codex 会话目录，默认 `~/.codex/sessions` |
| `--no-claude` / `--no-dsh` / `--no-codex` | 不读这个工具 |
| `--node 路径` | 指定 node，默认从 PATH 里找 |
| `--detail 文件` | 另把明细写到这个本地文件，见下面「隐私」 |
| `--sample N` | 明细里再附每个工具 N 条回合末尾的原文，用来校准正则。必须和 `--detail` 一起用 |

默认目录不存在的工具会自动跳过；你用参数指定的目录不存在会报错。

## 阶段配置

照 `阶段.example.json` 写：

- **时间写法**：ISO 8601。带 `Z` 的是 UTC；带 `+08:00` 这类后缀的按该时区，`+08:00` 就是北京时间；不带后缀的按运行脚本这台电脑的本地时间。建议都写上后缀，换电脑或换时区后不会算错。
- 每个工具一串阶段，按时间先后排。每个用户回合按它的**开始时间**归到「起」不晚于它的最后一个阶段。
- 第一个阶段「起」之前的回合不计；第一个阶段的「起」可以写 `null`，表示从最早的记录算起。
- 「截止」之后的记录一律不看。想复现某个时刻算出的结果，就把「截止」设成那个时刻；写 `null` 表示不设。
- 配置里没写的工具，整个算一个阶段「全部」。

## 读哪些记录、哪些不计

- **Claude Code**：`<目录>/<项目>/<会话>.jsonl`。
  - `subagents/` 下的子代理记录不计。
  - 续接会话会把旧会话的记录整段复制过来。这里按 uuid 去重，复制来的记录归最早的那个会话。
  - 工具自己插进对话的消息，比如后台任务通知、斜杠命令、系统提醒，不算用户发言。它们触发的续跑并进上一个回合。
- **DSH**：`<目录>/*/session-*/session.v4.jsonl.zstd`。
  - 有用户消息以「【调度说明】」开头的会话，是 Qlimen 派工脚本派出的工人，整个不计。
  - 按会话实际用的模型分组；用了不止一个模型的，记为「混用」。
- **Codex**：`<目录>` 下所有 `.jsonl`。
  - `session_meta.source` 不是字符串的会话（子代理、安全审查）不计。
  - `source` 是 `exec` 的单列，多半是被脚本或别的模型调起的工人。
- 超过 3 MB（Claude Code）或 2 MB（Codex）的单行记录直接跳过，多半是大段工具输出。汇总里会报跳过了几行。

## 口径

| 指标 | 怎么算 | 对应协议 |
|---|---|---|
| 回合 | 两条用户发言之间的全部记录 | — |
| 多步回合 | 工具调用 ≥ 5 次的回合。下面多数比例的分母是它 | — |
| 首条带状态标记 | 回合里第一段助手文字以【进行中】或【已完成】开头。分母是有文字的回合 | 第 5 节 |
| 阶段预告（窄） | 文字里有「第 N 步」「第 N/M 步」「共 N 步」 | 第 2 节 |
| 阶段预告（宽） | 窄口径之外，再加「第 N/M 项」「第一步」「阶段 N：」「步骤 N 做完」「Step N/M」「N/M 步」 | 第 2 节 |
| 写三件套 | 写或改 `方案.md`、`TODO.md`、`交接.md`：用写文件工具，或用命令行重定向、`tee`、`sed -i`、`perl -i` 改。Codex 从 `apply_patch`、`cat >` 这类代码文本里猜 | 第 6 节 |
| 区分已核实/未验证 | 文字里有「已核实」「未核实」「未验证」「没验证」「没核实」 | 第 1、2 节 |
| 先查后动 | 回合里第一次用写文件工具之前有几次工具调用，取中位。写文件工具：Claude Code 的 Write / Edit / MultiEdit / NotebookEdit；DSH 的 write / edit，不分大小写；Codex 是从代码文本里猜出来的写入。用命令行改三件套不算写文件工具 | 第 2 节「调研先行」 |
| 回合末交代 | 末段 = 最后一次工具调用之后的全部文字。末段里说清「在等你」「后台在跑 / 没在跑」「我接着做 / 收工」三类之一，就算交代了。「全末段」在整个末段里找；「含问句」另把末尾 3 行里有问号的也算；「末两行」只看最后两行，最严。以工具调用收尾的回合（被打断、报错）不进分母 | 第 5 节 |
| 耗时说明 | 「预计 / 大约 / 约 + 数字 + 分钟 / 小时」，或者「这段时间插不了话」。这一列连「用了约 3 分钟」这种事后说法也算 | 第 2、4 节 |
| 先说耗时再动手 | 更严：说完后面还有工具调用，且数字前面不是「用了」「耗时」「实际」这类过去式 | 第 2、4 节 |

**两种统计单位**

- **按回合**（汇总表第 1、2 节）：测的是协议动作出现的频率。
- **按会话 × 阶段**（第 3 节）：一个会话落在一个阶段里的那一段算一个单位，只计含多步回合的单位。
  - 「写过三件套」「阶段预告」「至少一次……」：单位里出现过一次就算，再除以单位数。
  - 「末尾交代率」：先算每个单位自己的交代率，再对单位取平均，长会话不会压过短会话。
  - 为什么要按会话算：一个长会话里，三件套往往开头建一次、之后反复更新，按回合算会被稀释。

**另外三张表**：会话有多长；Claude Code 会话形状（用户发言、后台通知、模型调用、工具调用、压缩次数、首尾跨度）；三件套写在多少个任务目录里（只数个数，不列路径）。

## 识别规则跟着协议措辞走

正则都在 `统计.py` 开头的「识别规则」一节，每条都注明对应 [core/rules/AGENTS.md](../../core/rules/AGENTS.md) 的哪一节。它们照 Qlimen 中文协议的原话写。下面这些情况要先改正则，否则会数成 0 或偏低：

- 状态标记换了写法；
- 三件套换了文件名；
- 阶段预告不说「第 N 步」；
- 协议换成英文。

改完用 `--detail 明细.json --sample 20` 抽几条回合末尾的原文，对一对有没有数错。

## 局限

- **全是正则，粗口径。** 作者抽查过几十条，没有系统算准确率和召回率。
  - 暗示式收尾（「你再试一下看看」）不算交代。
  - Codex 读和写分不开，它的三件套、先查后动两项更粗；用 Python `open(...,'w')` 写的三件套识别不了。
- **只看格式，看不到判断对不对。** 写过三件套不代表内容对，有阶段预告不代表估得准。两种单位测的都不是「遵守程度」：只回答问题的回合本来就不该写三件套；工人回回写阶段预告，频率高，其实是多余的。
- **不是对照实验。** 各阶段做的任务不一样，模型、软件版本、钩子、私有协议也可能同时变了，阶段之间的差异里混着这些因素。只能说「接入后观察到与条款一致的行为变化」，说不了因果。
- **样本。** 带 † 的行样本小（多步回合不到 20 个，或单位不到 5 个），只看方向。每个百分比后面都给了「命中数/分母」。
- **只评每个用户回合最后的结尾。** 回合中途停下来等后台通知的那些点，没有单独评。
- **会话记录格式会变。** 三个工具都没承诺记录格式不变，升级后可能读不对。哪一项突然全是 0，先怀疑格式变了。

## 隐私

- 脚本读的是你本机的会话记录。里面有你的对话原文、文件路径，可能还有密钥。脚本只读，不上传。
- 标准输出的汇总表只有：数字、阶段名和阶段时间、DSH 的模型名。不含对话原文、文件路径、会话编号。公开前还是自己看一遍：阶段名是你写的，阶段时间会透露你什么时候在用。
- `--detail` 写出的明细文件含会话编号和三件套的完整路径；加了 `--sample` 还含回合末尾的原文。这个文件只在本机看，不要提交到仓库，也不要公开。最好放在仓库外面；脚本发现它在某个 git 仓库里，会提醒你。
- 改过真实日期的阶段配置，也放在仓库外面。

## 和实测记录对得上吗

作者用自己的阶段配置跑过这个脚本，对照 [docs/实测记录.md](../../docs/实测记录.md) 第 2 节。下面这些全部一致：

- 「按会话统计」的表；
- 按回合的写三件套、末尾交代、耗时说明；
- 「先查后动」；
- 会话长度、三件套目录数。

按回合那张表有两处小差别，原因都是这里的口径改进了：

- **续接会话去重。** 第一轮按回合统计时，没给续接会话去重：Claude「只有 AGENTS」期多算了 7 个回合（268 → 261），精简期多算了 5 个（同一截止时刻 339 → 334）。首条状态标记、阶段预告、区分核实这几列因此差 1～2 个百分点。把去重关掉、三件套也照第一轮不认命令行写入，就和第一轮的数完全一样。
- **Codex 的三件套。** 第一轮只要「有写入，且代码里提到这三个文件名」就算。这里要求认得出写的是哪个文件，所以 Codex 主会话无协议期从 3% 变成 2%，工人精简期从 13% 变成 0%。工人精简期其实有写，用的是 Python 写入，两种规则都认不全。
