# Claude Code 适配说明

核心（`../../core/`）不依赖 Claude Code，本目录只写怎么接进去。
作者环境：Claude 桌面应用的 Code 会话 + 官方 Opus 5.5，2026-10。命令行版 Claude Code 读的是同一套 `~/.claude/`，按理一样，但作者没单独测过。

## 挂载点

| 东西 | 接到 Claude Code 的哪里 | 方式 |
|---|---|---|
| `core/rules/AGENTS.md` | `~/.claude/CLAUDE.md` 第 1 行 `@~/.claude/qlimen-AGENTS.md`（这个文件是指向核心的软链接） | `@` 引用 |
| Claude 私有协议 | `~/.claude/private-protocol.md`（实体文件，Claude 自己维护，不锁），`~/.claude/CLAUDE.md` 第 2 行 `@~/.claude/private-protocol.md` | `@` 引用；起步可以照 `examples/私有协议/claude-code.md` 改 |
| 工人名册 `core/skills/waibao` | `~/.claude/skills/waibao` | 软链接 |
| guard | `~/.claude/settings.json` 的 `hooks.PreToolUse`，匹配 `Bash` | 写进 settings；`install.sh` 用本目录 `hooks.example.json` 生成 `hooks.json` 给你参照，Claude Code 不读这个文件 |
| 派工脚本免弹框 | `~/.claude/settings.json` 的 `permissions.allow` 加 `Bash(<QLIMEN_HOME>/core/workers/waibao *)` | 写进 settings |

`$QLIMEN_HOME`（上表写成 `<QLIMEN_HOME>`）指 Qlimen 仓库的绝对路径，`install.sh` 运行时会打印出来；建议在 shell 配置里 export，或直接换成绝对路径。

`install.sh` 会建软链接，并把要加进 `settings.json` 的两段打印出来，由你自己粘贴（它不改你的 settings）。

## 手动接入（不用 install.sh 时）

```bash
ln -s "$QLIMEN_HOME/core/rules/AGENTS.md" ~/.claude/qlimen-AGENTS.md
printf '%s\n' '@~/.claude/qlimen-AGENTS.md' '@~/.claude/private-protocol.md' >> ~/.claude/CLAUDE.md
cp "$QLIMEN_HOME/examples/私有协议/claude-code.md" ~/.claude/private-protocol.md   # 再按你的情况改
mkdir -p ~/.claude/skills && ln -s "$QLIMEN_HOME/core/skills/waibao" ~/.claude/skills/waibao
```

然后把本目录 `hooks.example.json` 里的 `hooks` 段并进 `~/.claude/settings.json`，`{{QLIMEN_HOME}}` 换成你的绝对路径。

## 装好以后怎么查

- 新开一个会话，问「核心协议第 7 节讲什么」。答得出，就说明 `@` 引用生效了。
- `python3 "$QLIMEN_HOME/tests/guard/测guard.py" --installed`：测装好的那份 guard，100 条应该全过。
- 新会话里看技能列表里有没有 `waibao`。

## 已知限制

- 改 `~/.claude/CLAUDE.md` 要新开会话才加载；改 `settings.json` 的钩子、建 skill 链接，当场生效。
- 压缩之后：官方文档写明项目根目录的 `CLAUDE.md` 和自动记忆会重新注入；用户级 `~/.claude/CLAUDE.md` 和它 `@` 引用的文件，文档没逐字写。第一次压缩后，看一眼协议还在不在。
- guard 只看 Bash 命令的文本。故意绕的写法（把子命令放进变量、在 Python 里调用等）不管。定位是防顺手，不防故意。
- `settings.json` 加锁之后，应用自己在设置里改的东西也存不进去。要改设置时先运行 `$QLIMEN_HOME/core/bin/qlimen-unlock`，改完再运行 `$QLIMEN_HOME/core/bin/qlimen-lock`。
- `settings.json` 里写的是绝对路径。Qlimen 换了位置，按下面「仓库换了位置怎么办」来，光重跑 `install.sh` 修不好。

## 仓库换了位置怎么办

`预算.json`、`保护清单.txt`、`settings.json` 和各处软链接里写的都是绝对路径。光重跑 `install.sh` 修不好：`预算.json`、`保护清单.txt` 已存在就保留（里面还是旧路径），指向旧位置的链接会被当成「已存在」跳过。按下面的顺序来，`$QLIMEN_HOME` 指新位置：

1. 解锁：`$QLIMEN_HOME/core/bin/qlimen-unlock`。它按 `保护清单.txt` 里写的路径找文件，搬完再解，仓库里的文件按旧路径找不到、解不开（`~/.claude` 那几项照样能解）。所以最好搬之前在旧位置运行 `<旧位置>/core/bin/qlimen-unlock`；已经搬了，就先搬回去解锁再搬。
2. 改旧路径：把 `$QLIMEN_HOME/core/workers/预算.json` 和 `$QLIMEN_HOME/core/bin/保护清单.txt` 里的旧路径换成新路径（工作区跟着变了的话，`allow_roots` 和工人数据目录也在 `预算.json` 里）。或者先备份这两个文件，运行 `"$QLIMEN_HOME/install.sh" --apply --force` 重新生成，再把自己改过的数字填回去：`--force` 会把它们重置成模板值。
3. 重建链接：删掉指向旧位置的 `~/.claude/qlimen-AGENTS.md` 和 `~/.claude/skills/waibao`，再运行 `"$QLIMEN_HOME/install.sh" --apply --link claude`（还用别的环境就一起写上，如 `--link claude,codex,dsh`）。
4. 更新 `~/.claude/settings.json`：guard 钩子的命令和 `permissions.allow` 里 waibao 的路径换成新位置，`install.sh` 最后打印的那两段就是新路径。用到 Codex、DSH 的，按各自的挂载说明更新钩子配置。
5. 跑测试：`python3 "$QLIMEN_HOME/tests/跑全部测试.py"`，再 `python3 "$QLIMEN_HOME/tests/guard/测guard.py" --installed`（这一条读环境变量 `QLIMEN_HOME`，没设时测的是 `~/Qlimen`）。
6. 加锁：`$QLIMEN_HOME/core/bin/qlimen-lock`，再用 `$QLIMEN_HOME/core/bin/qlimen-lock --status` 看一眼，列出来的应该都是新路径、都已锁上。
