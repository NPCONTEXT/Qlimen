# Claude 桌面应用：卡片吞正文、灰字建议、两个插件

本页只管 Claude 桌面应用（macOS）的 Code 会话。作者环境：桌面应用 4.4212.0、Claude Code 2.1.309、Opus 5.5（2026-10-30）。数字都是作者在自己机器上数的，换了版本可能不一样。

## 一、原生卡片「吞」正文

### 现象

- 一轮里，Claude 在**工具结果之后、下一个工具调用之前**写给你的话，约三分之二在界面上整段不显示：会话记录里没有正文，只剩一个思考块，内容是那段话的改写摘要。
- 提问卡片（AskUserQuestion）前面那段话，总在「工具结果之后」这个位置。所以卡片弹出来时，前面交代的命令、汇报常常看不到，就得做决定。
- 不受影响的：紧跟你消息的第一段（Claude 动手之前写的），和每轮最后一条正文。

### 数据（作者本机的会话记录，2026-10）

| 位置 | 被改写 / 写了话的 |
|---|---|
| 工具结果之后、后面还有工具调用（10-28～10-30，应用升级前） | 411 / 633（65%） |
| 同上，应用升到 4.4212.0 之后 | 100 / 156（64%） |
| 紧跟用户消息的第一段 | 0 / 140 |
| 每轮最后一条（前面跑过工具） | 0 / 201 |

10-30 又在同一个会话里弹了两张测试卡片：接在工具结果后面的那段被改写、作者在界面上找不到；紧跟用户消息的那段留着。

### 原因

没查清。被改写的思考块带着接口签名，像是接口返回时就已经是思考块，不是应用显示时弄丢的（推断）。应用升级前后比例一样，光更新应用多半修不好。

### 对策

作者的私有协议里就是这么写的（见 `examples/私有协议/claude-code.md`「高频翻车」）：

1. 要你读、做、拍板的内容，放在这一轮的最后一条正文。工具调用之间的过程话，当作你可能看不到，要紧的收尾时再说一遍。
2. 用提问卡片，就把要点全写进卡片：
   - 问题开头先写要定什么（会话列表的悬停浮层只显示前面一截），再写背景和数字。约 200 字的问题加三条约 40 字的选项说明，一眼看得全。
   - 选项说明写「选了会怎样」。选项里谁做就写谁：Claude 写「Claude」，你写「你」，不用「我」（作者看反过两次）。
   - 网址直接写，卡片里能点；文件链接在卡片里点不开，写目录加文件名；选项的 preview 桌面不显示，别用。
   - 卡片前那段只写过程话。
3. 能在一轮开头弹卡片，就在开头弹：紧跟你消息的那段不会被改写。
4. 要你动手、要花时间的事（测试、验收、粘贴命令、登录），不用卡片：正文写全，结束这一轮，等你说做完。
5. 没用的办法：先写一步文件再弹卡片（10-27 实测，后面接写文件的 35 段里 27 段照样被改写）。

### 自己数

会话记录在 `~/.claude/projects/<项目>/<会话>.jsonl`。把 assistant 记录按 `message.id` 合并块（thinking / text / tool_use），再看前一条记录是用户消息还是工具结果：有正文块的是正常的；没有正文、只有带字的思考块的，就是被改写的（作者环境里，真正的思考在记录里存成空的）。

## 二、灰字建议的两条路

官方的灰字建议（Prompt suggestions：回复完后，输入框里出现灰色的下一句，按 Tab 采用）在桌面应用里时有时无：会话挂了任务框就不请求建议（[anthropics/claude-code#88391](https://github.com/anthropics/claude-code/issues/88391)，2026-10-30 还开着），另外还有线上开关。开源版预设两条路，免得哪天官方又改掉建议上屏的机制。两条可以同时走：原生灰字在输入框里，插件的建议在输入框上方。

### 第一条：禁用原生 TODO，恢复原生建议

在会话工作目录的 `.claude/settings.json` 里加（已有 `permissions.deny` 的，把这一项加进去）：

```json
{
  "permissions": {
    "deny": ["mcp__ccd_turn"]
  }
}
```

- 效果：桌面应用 4.4212.0 起，新建会话时会读这个目录的设置。应用任务清单的两个工具（`update_plan`、`wrap_up`）都被禁，就不挂任务框；不挂任务框，原生灰字就回来了（作者 10-30 实测）。
- 代价：这些会话没有应用原生的任务清单和收尾卡片，进度由 Claude 照 Qlimen 用文字说。
- 限制：只管设置写好以后新建、工作目录就是这个目录的会话，老会话照旧没有；工作目录是子目录的会话管不管，没测。应用设置里的 Prompt suggestions 要开着。这是应用没写进文档的行为，以后的版本可能失效，失效了就靠第二条。
- 自动模式下让 Claude 改这个文件，会被安全检查拦下（作者 10-27 遇到过），自己动手改。
- 核对：改完新开一个会话，等第一条回复完，看输入框里有没有灰字。

### 第二条：装平替插件

`plugins/suggest-bar/`：每轮回复完，用模型猜你的下一句，显示在输入框上方，点「填入」或「直接发送」。不管官方怎么改都在；代价是每轮一次模型调用（默认 Opus，几百 token；`/suggest off` 关掉就不花）。详见 [说明](plugins/suggest-bar/说明.md)。

## 三、两个插件

| 插件 | 做什么 | 说明 |
|---|---|---|
| `plugins/context-bar/` | 输入框上方显示上下文用量；快满时提醒交接；「交接并压缩」一键写好交接再压缩；压缩摘要用中文写 | [说明](plugins/context-bar/说明.md) |
| `plugins/suggest-bar/` | 平替灰字建议：猜你的下一句；收起、展开、完全关闭三档 | [说明](plugins/suggest-bar/说明.md) |

- 装法都是把文件夹复制到 `~/.claude/skills/<名字>/`，新开的会话自动加载；只装一个也行。复制命令见各自的说明，里面的 `$QLIMEN_HOME` 指你放 Qlimen 仓库的绝对路径（`install.sh` 运行时会打印出来），没设就直接换成路径。
- 两个插件都用 Claude Code 的模组机制：`.claude-plugin/plugin.json` 加 `hooks/hooks.json`，后者指向 `hooks/register.tsx`。改了要新开会话才生效。
- 测试：`claude plugin test <插件文件夹>`（上下文横条 25 个、建议横条 29 个，都用假的模型和用量，不花钱）。
