# DeepSeek Harness（DSH）适配说明

核心（`../../core/`）不依赖 DSH。换一个 harness 时，只重写本目录。
作者环境：DeepSeek Harness 桌面应用 `0.2.0-rc.2`。主模型先后用过 DeepSeek flash 和经中转站接入的 Opus；派工时，flash 工人也走 DSH 的无头模式。

## 挂载点

| 东西 | 接到 DSH 的哪里 | 方式 |
|---|---|---|
| `core/rules/AGENTS.md` | `~/.dsh/AGENTS.md` | 软链接（DSH 实测会跟随） |
| 工人名册 `core/skills/waibao` | `~/.dsh/skills/waibao` | 软链接（DSH 实测能发现） |
| DSH 私有协议 | `~/.dsh/private-protocol.md`（实体文件，DSH 自己维护，不锁） | `hooks.json` 的 `SessionStart` 调 `hooks/private-protocol` 送进上下文；起步可以照 `examples/私有协议/dsh.md` 改 |
| 本目录 `hooks.json`（`install.sh` 用 `hooks.example.json` 生成） | `~/.dsh/profiles/desktop/cordis.patch.yml` 末尾加上 `cordis-hooks.patch.yml` 的内容（同样由 `.example.yml` 生成） | 插件 `@deepseek-ai/dsh-hooks-claude-code`（DSH 自带的 Claude Code 钩子桥） |
| `dsh-flash.patch.yml` | waibao 派 flash 时 `dsh headless --patch` | 命令行参数，不用挂 |

## 钩子

| 事件 | 脚本 | 作用 | 钩子坏了时 |
|---|---|---|---|
| SessionStart | `hooks/private-protocol` | 把 DSH 私有协议送进上下文 | 报钩子失败，会话照常 |
| UserPromptSubmit | `hooks/intake` | 每轮附一段提示：先分清「只评价」还是「新需求」，新需求按核心 §2 先调研、写方案、等批准。DSH 的协议会被自动压缩压掉，这是唯一的每轮提醒 | 静默放行 |
| PreToolUse（bash） | `core/workers/guard` | 不经 waibao 直接调 `dsh headless` / `kimi -p` 时问用户 | 放行 |

**作者踩过的坑**
- **私有协议钩子**：最早用 `/bin/cat`（纯 stdout）送私有协议，一直没生效。桥接只认 JSON 里的 `hookSpecificOutput.additionalContext`（依据：桥接的 `parseHookOutput()` 只在 stdout 以 `{` 开头时读结构化字段）。换成现在这个脚本后，2026-10-08 新会话实测生效。
- **压缩**：私有协议压缩后会不会再送一次，没核实。
- **guard 的 `ask`**：桥接 README 写明支持 `ask`；2026-10-09 实测会弹框，等用户点允许才执行。判断有没有弹过框，不能看命令最后有没有执行：那次命令照常有输出，一度误以为没弹框，实际是弹框等了 36 秒、点了「允许一次」才执行（见 `examples/私有协议/dsh.md`）。
- **对话内容**：钩子在会话工作区目录里运行，`transcript_path` 永远为空，钩子读不到对话内容。

## 手动接入

`$QLIMEN_HOME` 指 Qlimen 仓库的绝对路径，`install.sh` 运行时会打印出来；建议在 shell 配置里 export，或直接换成绝对路径。

```bash
ln -s "$QLIMEN_HOME/core/rules/AGENTS.md" ~/.dsh/AGENTS.md
mkdir -p ~/.dsh/skills && ln -s "$QLIMEN_HOME/core/skills/waibao" ~/.dsh/skills/waibao
cp "$QLIMEN_HOME/examples/私有协议/dsh.md" ~/.dsh/private-protocol.md
```

运行 `install.sh --apply`，它会用 `hooks.example.json`、`cordis-hooks.patch.example.yml` 生成填好路径的 `hooks.json`、`cordis-hooks.patch.yml`。把 `cordis-hooks.patch.yml` 的内容追加到 `~/.dsh/profiles/desktop/cordis.patch.yml` 末尾，重启 DSH。

## 做不到的

- 上下文快满时自动写交接，在钩子这一层做不到：桥接不支持 `PreCompact` / `SessionEnd`，模型也拿不到上下文用量。DSH 自动压缩（默认窗口 80% 时触发）用的是内置英文摘要提示，不读交接。所以「交接要勤写」写进了 DSH 私有协议。
- 钩子桥是 `0.2.0-rc` 的实验版：只支持 command 钩子；`Stop` 的 `stop_hook_active` 永远是 false（已归档的 finish-check 因此自己限了次数）。
- 配置在进程启动时读一次，改 `hooks.json` 要重启 DSH。
- `UserPromptSubmit` 的提示对强模型是加固，对弱模型只是提醒。真正兜底的是加锁和 guard。
- 任务目录里放名为 `AGENTS.md` 的文件，会被 DSH 当成该目录的指令加载。草稿别用这个名字。

## Kimi

`~/.kimi-code/AGENTS.md` 也可以链到核心。但 `kimi -p --agent-file` 的工人模式不注入全局协议（2026-10-05 冒烟确认），工人靠 `core/workers/工人守则*.md`，见 `../kimi/说明.md`。

## 撤掉

`$QLIMEN_HOME/core/bin/qlimen-unlock` → 删掉 `~/.dsh/profiles/desktop/cordis.patch.yml` 末尾 `qlimen-hooks` 那段 → `$QLIMEN_HOME/core/bin/qlimen-lock` → 重启 DSH。
