# 方案：把 Qlimen 接进 Codex（v2）

> 示例：这是一次真实任务的方案原件，经过脱敏（路径换成占位，个人 skill 名泛化，文档链接改成文字出处，时刻只留日期，部分用户原话改成转述）。用来看「方案」长什么样：调研分已核实 / 未核实、目标与不做什么、做法、可机器查的验收清单、花费、风险与回滚。

v1 写于 2026-10-08；v2 按用户意见改，用户 10-08 批准：「核心这两处按 diff 改，Codex 接入按新方案做」。

用户要求（10-08，转述）：由我把这套 Harness 接进 Codex，不让 Codex 自己接（担心它改动核心协议）；接好后给 Codex 写一份交接，写明它接下来要做什么。
v2 的由来（10-08）：用户说「新的AGENTS要求不要把杂七杂八的写进去」，问入口是直接替换还是另有修改方案。另外两点（转述）：旧的写作指引段可能是 Codex 自己把 skill 写进去的，用户平时都正常调用 skill；核心可以补一条，如无必要不建副本，确需副本要在维护一节写明位置和原因。

## 调研结果

已核实（2026-10-08，本机）：
- Codex 是 ChatGPT 桌面应用里的那个，命令行在 `/Applications/ChatGPT.app/Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex`，版本 `codex-cli 0.162.0-alpha.2`；`PATH` 里没有 `codex`。
- `codex debug prompt-input` 能在本地打印模型实际看到的输入，不调模型。用它在临时 `CODEX_HOME`（`/tmp/codexprobe/home`）测过：`AGENTS.md` 做成指向核心的软链接，Codex 跟随，核心全文进了模型输入；`skills/` 下的软链接被列进 skill 清单。
- 旧 `~/.codex/AGENTS.md`（880 字节）只有一段「个人写作 skill」指引；写作 skill 本身在 `~/.agents/skills/` 下，Codex 已自动列出它。那段指引里，「开头一句话说明 skill 和范围」「已授权出稿就完成」「先整理就停」「只润色不核查不重排」skill 正文都有；skill 没有的只剩「固定路径可用时不再翻下载压缩包，也不凭记忆摘要代替读取」「入口缺失或不可读先说明，不把泛化初稿当作按 skill 产出」「后续局部修改沿用它」。
- 没有 `AGENTS.override.md`、没有 `hooks.json`；`codex features list` 里 `hooks` 为 stable、已开。
- 现有入口全是链接、没有副本：`~/.dsh/AGENTS.md`、`~/.kimi-code/AGENTS.md`、`~/.claude/qlimen-AGENTS.md`、`<工作区>/工人家.nosync/{dsh,kimi}/AGENTS.md`。
- 「各工具目录下的 AGENTS.md 是它的链接或同步副本，不要直接改副本」这句在最早的备份（`<工作区>/任务-Qlimen/备份/交接机制-20261005/AGENTS.md`）里已有。

已核实（Codex 官方文档的 AGENTS.md 页和 hooks 页，10-08 读）：
- 全局只取 `~/.codex/` 下第一个非空的 `AGENTS.override.md` 或 `AGENTS.md`；文档没提 `@` 引用。
- 钩子写在 `~/.codex/hooks.json`。`PreToolUse` 的 shell 命令 `tool_name` 是 `Bash`、命令在 `tool_input.command`，拒绝格式和 Claude 相同。`SessionStart` 的 matcher 有 startup / resume / clear / compact，不写 matcher 就全匹配；它的标准输出会作为开发者上下文加进去。
- 新建或改过的钩子要先信任才运行（文档写「在 CLI 里用 `/hooks`」），按钩子定义的哈希记。

未核实（交给 Codex 在真实会话里查）：桌面应用能不能信任钩子；guard 和私有协议注入在真实会话里是否生效；Codex 沙箱里能不能跑 `waibao`；压缩后核心协议还在不在；后台命令跑完会不会叫醒她。

## 目标与不做什么

目标：Codex 每次开会话都带着核心协议原文；她的私有协议靠钩子送进上下文、她自己维护；能用工人名册；guard 挂上；入口和钩子配置锁住，她改不了。核心按用户批准的 diff 改两处。
不做：核心协议只改批准的两处；不改 guard、waibao；不改 Codex 的 `config.toml`、记忆、写作 skill；不在 Codex 里调任何模型；不替 Codex 写她的私有协议正文（只放已核实的种子事实和搬来的三句）。

## 做法

- 入口 `~/.codex/AGENTS.md` 改成指向核心原文的软链接，不加任何东西。旧文件原样备份到 `备份/`（作者本机，未收录）。
- 私有协议 `~/.codex/private-protocol.md`：种子事实 + 待核实清单 + 写作指引里 skill 没覆盖的三句。不锁，Codex 自己维护。
- `~/.codex/hooks.json`：`SessionStart`（不写 matcher）用 `/bin/cat` 把私有协议送进上下文；`PreToolUse`（匹配 `Bash`）挂 guard。
- skill：`~/.codex/skills/` 下建 `waibao`、`history-archive`、`skill-authoring` 三个软链接，和 Claude 侧一致。
- 核心协议改两处（diff 见 TODO 第 5 步）；保护清单加 `~/.codex/AGENTS.md`、`~/.codex/hooks.json`。
- `adapters/codex/挂载说明.md` 写挂载点、钩子、怎么查、回滚；`交接-给Codex.md`（作者本机文件，未收录） 写她接下来做什么。

## 验收清单

1. `readlink ~/.codex/AGENTS.md` 等于核心原文路径（机器查）。
2. 在临时目录跑 `codex debug prompt-input`：AGENTS 段含核心第 2 节和第 7 节标题，不再含写作那段；skill 清单里有 `waibao`、`history-archive`、`skill-authoring` 和写作 skill（机器查）。
3. `hooks.json` 是合法 JSON；guard 存在且可执行；`/bin/cat` 那条命令能输出私有协议（机器查）。
4. 用 Codex 格式的样例喂 guard：直接调 dsh 无头模式 → deny；`ls` → 无输出；经 waibao 调用 → 无输出（机器查）。
5. 核心改完，与改前备份 `diff`，只有批准的两处（机器查）。
6. 用户 `qlimen-lock` 后，`qlimen-lock --status` 里新增两个路径显示已锁（机器查）。
7. 交接里的每个路径用 `ls` 核存在（机器查）。

## 花费

零。全是本地文件操作；`codex debug prompt-input` 不调模型。

## 风险与回滚

- 钩子没被信任，或桌面应用不跑钩子：guard 不拦、私有协议不自动进上下文，但核心协议照常加载。私有协议开头写了「钩子没生效就自己读本文件」，由 Codex 实测后定退路，退路要动入口就先问用户。
- 回滚：用户 `qlimen-unlock` → 用 `备份/`（作者本机，未收录） 里的原文件换回 `~/.codex/AGENTS.md`、删 `~/.codex/hooks.json` 和 3 个 skill 链接、保护清单删两行；核心用任务目录 `备份/` 里的改前原文换回 → `qlimen-lock`。
