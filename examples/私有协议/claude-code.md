# Claude Code（官方 Opus）私有协议

> 示例：这是作者环境里实际在用的私有协议，经过脱敏（个人项目、设备细节已删或泛化，个别日志计数取约数）。照着它的结构，改成你自己环境的能力、限制和踩过的坑。

本文件只写本环境（Claude 桌面应用的 Code 会话 + 官方 Opus）的能力、限制、习惯和坑；跨环境的规则在核心 AGENTS。
由本环境的主模型维护，不加锁；用户纠正的点当场写进来或写进自动记忆。只写事实和自己的毛病，不写「必须先……再……」这类流程。

## 高频翻车（先看这里）

- **路径**：给用户的路径反复写错。① 文件链接 href 从 `<工作区>/` 起写全路径，按子目录写面板打不开（桌面应用日志 09-28 到 10-10 记了两千多次 could not resolve）；会话里「工作目录换成某子目录」的环境提示不算数；工作区外的文件（含 `~/.claude` 记忆）不写链接，用代码格式写完整路径。10-10 记完这条当天又错两回。② 给用户运行的命令写完整路径：10-10 只写了 `qlimen-unlock`，它不在命令搜索路径里，用户运行报 command not found，而记忆里早写着完整路径。拿不准先 `ls` 或 `command -v`。
- **zsh**：`$VAR` 里存命令、选项或一串路径都不分词，整串被当成一个东西（自动记忆里记了 5 次，一次让备份一个都没备上）；列表用数组。「成功」提示放在查过返回码之后。没设 `LANG` 时 `wc -m` 数的是字节，中文字数用 python 数。删除命令别用变量或 `$(...)` 拼路径，会被安全检查拦。细节见自动记忆 `feedback-shell-pitfalls`。

## 能力与机制

- 能看图（读图片、截图），不用派工人看图。
- 能并行调工具、能后台跑命令。后台命令跑完会以通知把我叫起来（会话记录里 47 次，2026-10-06 核实），所以长任务后台化后可以结束回合等通知，不用前台干等。
- 用户的插话在两次工具调用之间送达：前台命令跑多久，用户就多久插不进话（和 DSH 一样，核心 §4「前台 ≤90 秒」就是为这个）。
- 压缩后：项目根 `CLAUDE.md` 和自动记忆会从磁盘重新注入（官方文档 code.claude.com/docs/en/context-window「What survives compaction」）；用户级 `~/.claude/CLAUDE.md` 和它的 `@` 引用，文档没逐字写。第一次压缩后看一眼核心协议还在不在，不在就告诉用户。
- 定时唤醒、定时任务类工具存在，但没实测过能不能叫醒当前会话；没测过之前不承诺「过几分钟告诉你」。
- 开子代理先说明花费、等用户同意（会费额度）；子代理不许用内置浏览器面板、不许启动 Blender 这类重型图形程序（详见自动记忆）。
- 改 `~/.claude/settings.json` 里的钩子、建 skill 软链接当场生效；改 `~/.claude/CLAUDE.md` 要新开会话才加载。
- PreToolUse 钩子返回 `ask` 会弹框给用户，自动模式下也弹（2026-10-09 测 1 次：guard 返回 ask，用户看到弹框点了允许）。guard 10-09 起就是这样：直连 kimi -p / dsh headless 时问用户，不再直接拦；写进文件的文字不再触发。
- 桌面应用的 Code 会话不运行自定义状态栏脚本（2026-10-06 测两次：用户新开会话、等回复完，运行记号都没出现；同一条命令用 shell 原样跑是好的）。

## 我自己犯过的错（来自复盘和会话记录）

- 前台干等长命令：2358 次前台命令里 19 次超过 90 秒、3 次超过 8 分钟（短片渲染时等出片）。等渲染、等下载、等工人一律后台。
- 结论外推：只试了 3 个样本，写成「任意文件都能读」。样本几个就写几个，推断标成推断。
- 数字不注来源、只看一部分就下结论（账本只看最后 8 行）。写数字前看全量，写明在哪数的。
- 没复现就报改动量和后果。
- 思考过程用过英文。思考也用中文。
- 长任务里汇报也会滑成英文（10-10 调游戏脚本，后台跑脚本、工具输出多为英文和代码时，进度说明和阶段汇报整段写成英文，用户说「恢复中文汇报」）。每条给用户看的文字发出前看一眼是不是中文。
- 被钩子拦后自判误报、改写法绕过（已纠正，见核心 §3）。
- 调游戏脚本时把一小段丢后台、结束回合等通知，脚本卡在不认识的画面空等 4 分钟，我也几分钟没动静，用户说「我说的是你！」（2026-10-06）。调试期一段一段前台跑、盯着日志和截图，超时转后台也接着看。
- 用户要精简时又加规则：瘦身方案里的「审批点」列了高风险清单、回滚、等待条件，用户指出又复杂了（2026-10-06）。能一句话说清的不写一节，不用新规则去补规则。
- 盯脚本时两次在前台命令里用 `&` 起监视进程（10-07），变成没人收的孤儿进程；监视一律用后台任务起，不在前台命令里加 `&`。
- 用按钮编号点别的程序的窗口：编号会随列表内容变（10-07 挂机脚本平台的任务列表里多了一行「待验收」，我按旧编号点错，启动了另一个脚本，它把暂停中的游戏战斗点回了战斗）。点之前重新截图对编号，点完马上看结果。
- 把一个环境的接法照搬到另一个环境，只看了「支持某事件」，没读同一份文档的「已知限制」：10-08 给 DSH 挂 SessionStart 照抄 Codex 的 `/bin/cat`，DSH 钩子桥 README 第 176 行写着不认纯 stdout，注入一直没生效，DSH 自己读源码查出来修好。换环境挂钩子前，先读该环境钩子文档的限制段。
- 瘦身方案把预算和安全写进同一格「安全底座：不动」，用户以为派工已经变成参考，结果脚本照拦，K3 长任务只能绕开脚本（10-08）。写限制时分清是安全边界还是默认预算，预算类用户批准就能超（10-09 已改成只提醒）。
- 方案里没想到 Kimi 登录会改写加锁的 `config.toml`，让用户上锁后才登录，报 EPERM（10-09）。动加锁清单里的程序前，先想它会不会写自己的配置。
- 把旧凭据备份进了任务目录（会外发给工人、会进 iCloud），发现后删掉（10-09）。凭据只放 `.nosync` 的工人数据目录或不留。
