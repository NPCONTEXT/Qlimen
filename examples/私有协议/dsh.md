# DSH 私有协议

> 示例：这是作者环境里实际在用的私有协议，经过脱敏（个人项目和 skill 名已泛化）。照着它的结构，改成你自己环境的能力、限制和踩过的坑。

本文件只写本环境（DeepSeek Harness 桌面应用，简称 DSH）的能力、限制、习惯和坑；跨环境的规则在核心协议（`~/.dsh/AGENTS.md`，链接到 `$QLIMEN_HOME/core/rules/AGENTS.md`）。
由 DSH 的主模型自己维护，不加锁；用户纠正的点当场写进来。只写事实和自己的毛病，不写「必须先……再……」这类流程。
会话开始时，钩子（`$QLIMEN_HOME/adapters/dsh/hooks.json` 的 `SessionStart`，2026-10-08 修好后指向 `adapters/dsh/hooks/private-protocol`）会把本文件送进上下文；上下文里没看到本文件时，自己 read 一遍。

## 本文件和按需记忆怎么分（2026-10-08 用户定，10-09 补后两条）

- 本文件每次会话都会送进来，只放换一个完全不相关的任务也用得上的：环境能力、长期习惯、自己犯过的错。
- 其余放 `<工作区>/记忆/` 按需读（在工作区里，写时不用申请沙箱）：`通用/` 放工具用法和查东西的法子，`任务经验/` 一类任务一个文件。新建文件时，在本文件末尾「按需读」加一行「什么时候读 → 哪个文件」。
- 证据和过程（会话编号、时间戳、怎么查出来的）写任务目录的交接，记忆里留结论和出处。
- 整理时整句挪，不改写；记忆变多是正常的，不为精简而删（用户 10-08：「单纯控制字数容易为了精简而精简」）。
- 每条事实后带最后核实日期；状态未定的不写进正文，放末尾「待核实」，核实一条就搬上来并删掉那条。
- 分类按「用得上」而不是「重要」：只在某类任务里用得到的（哪怕很重要）也放记忆，正文只留一句指路（10-09 定）。

## 能力与机制

- 入口 `~/.dsh/AGENTS.md` 是指向核心原文的软链接，DSH 跟随读取（10-05 实测）。
- skill：`~/.dsh/skills/` 下 `waibao`（工人名册）、`history-archive` 是指向 Qlimen 的软链接，DSH 能发现（10-05 实测）；另有几个是实体目录（`skill-authoring`，以及游戏日常脚本、网页数据采集两个个人任务的 skill）。新 skill 写 `~/.dsh/skills/<kebab-case-名>/SKILL.md`。
- 任务目录里放名为 `AGENTS.md` 的文件，会被 DSH 当成该目录的指令加载（10-05 踩过）；草稿别用这个名字。
- 现在挂的钩子（`adapters/dsh/hooks.json`，加锁）：SessionStart（送入本文件；10-08 修好并实测注入成功）；UserPromptSubmit（intake，每轮提示先分清「只评价」还是「新需求」）；PreToolUse/bash（guard：不经 `waibao` 直接调 dsh 无头模式 / kimi 提示词模式的命令，**弹确认框问用户**，用户点了才执行；2026-10-09 实测）。
- 注入进上下文时**以 user 角色消息出现、正文原样进来**（不是 system 提示），所以会话记录里看着像"用户发了一段协议"，别误判（10-08 实测）。
- 自动压缩 `dsh-compaction-basic`：默认在上下文窗口约 80% 时触发，摘要用内置英文模板，不读交接 ⇒ 交接要勤写；压缩后协议还在不在见「待核实」（9/15 记的旧版行为未在新版复测）。
- 默认主模型在 `~/.dsh/profiles/desktop/cordis.patch.yml` 的 `agent-default-model`（10-08 是三方中转的 `claude-opus-5-5`）；用户也会换成 DeepSeek 跑。看图派 `flash`，看不清再派 `k3`（名册见 skill `waibao`）。
- 后台任务跑完会叫醒我：10-08 实测，后台任务结束的提示会作为会话内消息送进来，我在同一个回合就能用 `job_output` 取结果，不用用户再发一条。
- 当前会话的审批策略与文件权限：不固定，以每次会话开头系统提示里的 `Current DSH file policy` / `Approval policy` 为准（10-08 是 `workspace-write` + `ask`；10-05 记的 `never` + `danger-full-access` 是当时的设置，别当默认）。**写工作区外被拒时先分清是沙箱还是加锁**：沙箱拒（文案 `[sandbox: file access denied under workspace-write mode]`）⇒ 带 `sandbox_permissions` 重试一次、由用户批准（写本文件就是这样过的）；加锁拒（`Operation not permitted`，`ls -lO` 可见 `uchg`）⇒ 停，出 diff 请用户解锁。判断一件东西该不该等用户：`ls -lO <文件>` 看有没有 `uchg`，再 `grep <文件名> $QLIMEN_HOME/core/bin/保护清单.txt`；两项都没有就是没加锁，直接改（10-08 用户纠正）。产物一律放工作区：工作区外的系统下载目录权限位虽属主可写，`workspace-write` 下同样不可写、写入要批准（10-09 实测）。

## 我自己犯过的错

- `set -u` 的 bash 脚本里，变量名后面紧跟中文（如 `$B。`）会被当成变量名的一部分，报 unbound variable；变量一律写成 `${B}`（10-05）。
- 判断钩子有没有问过用户，**不能看命令最后有没有执行**：2026-10-09 我跑 `true || kimi -p 测试`，看到命令有输出就以为「没弹框、ask 被忽略」；实际是弹框等了 36 秒、有人点了「允许一次」才执行。查法与证据（`approval/*` 事件、时间差、源码）见记忆。
- 把「过时描述要改」和「文件加锁」混为一谈：`adapters/dsh/挂载说明.md` 从没进过保护清单、也没有 `uchg`，我却对用户说「要你解锁才能改」，白等一轮（用户 10-08 纠正）。
